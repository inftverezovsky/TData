# Ошибка импорта Prisma `void`: проверка и исправление

Дата: 07.09.2026. База проверки: `origin/main` / `7121548`.

## Причина

Три запроса Liquipedia возвращали `pg_advisory_xact_lock(...)` как колонку
результата. PostgreSQL возвращает из этой функции `void`, который Prisma 5.22
не десериализует. Ошибка возникала при сохранении турнира, публикации последнего
успешного снимка источника и обновлении диагностики.

Общая функция `backend/src/db/advisoryLock.ts` выполняет блокировку в `FROM`,
возвращая поддерживаемое целое число. Все шесть мест блокировки импорта теперь
используют её. Ключи, параметризация, порядок получения блокировок и границы
транзакций сохранены; изменения схемы БД не требуются.

## Охват источников

Проверены реестр, диспетчер и пути сохранения всех 13 источников: Liquipedia,
HLTV, VLR, DLTV, Fandom, Volleyball World, beach.volley.ru, German Beach Tour,
12ndr CSVP, 12ndr ÖVV, CBV, Federvolley и WTT. Оба источника 12ndr используют
общую реализацию. У остальных импортёров запросы блокировок уже возвращали
поддерживаемый тип; дополнительной общей причины отказа при анализе не найдено.

Это проверка кода и тестовых сценариев, а не гарантия доступности каждого
внешнего сайта. Например, HTTP 403/Cloudflare от HLTV относится к доступу к
источнику и не устраняется изменением SQL. Монитор источников проверяет загрузку
и нормализацию, поэтому его успешный ответ не заменяет тест сохранения в БД.

## Проверки

- `npm run check`: TypeScript, ESLint, 1028 тестов — успешно.
- `npm run test:integration`: 42 теста на отдельном локальном PostgreSQL 18.6 — успешно.
- `npm run build`: production-сборка — успешно.
- `npm run test:e2e:prod -- --workers=2`: 44 сценария — успешно; один отдельный
  сценарий отправки в mock Admin API пропущен штатно без `RUN_DB_E2E=1`.
- Новая функция блокировки: 100% строк, ветвей и функций.
- `npm audit`: уязвимости не найдены.

Новый DB-тест сначала воспроизводит исходную ошибку реальным драйвером Prisma,
затем проверяет поддерживаемый результат, взаимное исключение транзакций и
освобождение блокировки после commit/rollback. Проверяется реальная публикация
кэша Liquipedia. Отдельные сценарии Dota2, Counter-Strike, LoL и Valorant выполняют
настоящий рекурсивный импорт основной страницы и подстраницы из тестовых
снимков: сохраняют два матча, четыре участника, статус SUCCESS, оба кэша и
объединённую диагностику. Внешние сетевые обращения в этих тестах запрещены.
Существующие DB-тесты подтверждают сохранение предыдущего
расписания, ручных привязок и защиту от конкурентного устаревшего импорта.

Все изменяющие БД тесты проходят `requireTestDatabaseUrl`; рабочая БД для них
не используется. Первый браузерный запуск без тестовой БД выявил ожидаемый
отказ DB-зависимого входа (503). Повторный полный запуск выполнен после миграций
и seed отдельной тестовой БД и прошёл.

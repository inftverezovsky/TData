# Аудит и приведение TData в порядок

Дата: **7 сентября 2026 года**. Объект: локальная рабочая копия TData,
исходная ветка `codex/TData`, исходный коммит `76256f4`.

## Результат для руководителя

Проект получил понятную карту ответственности, русские комментарии к основным
алгоритмам и воспроизводимые проверки. В ходе аудита устранены не только проблемы
читаемости, но и ошибки сохранения данных, очереди изображений, настроек и защиты
запросов. Подготовлены документы для передачи проекта другому разработчику.

Основная структура `frontend/` + `backend/` сохранена: она соответствует существующему
Next.js-приложению. Из самого большого UI-файла выделены самостоятельные части;
из сценария импорта — проверка параметров и транзакционное сохранение.

**Локальные проверки не заменяют проверку production.** Оставшиеся эксплуатационные
риски перечислены ниже. Выкладывать изменения следует после решения вопроса доступа
к внешним отправкам и проверки конфигурации рабочего окружения.

## Читаемость и структура

- `ManualImportWorkbench.tsx`: **2542 → 475 строк**. Состояние, распознавание,
  изображения, сопоставления, таблица и отправка выделены в hooks по 125–246 строк.
  Проверка HTTP-ответов отделена от UI.
- `TeamMappingPanel.tsx`: 192 строки UI, отдельный контроллер, модель и combobox.
- Четыре нормализатора: entrypoint по 161–205 строк; HTML/wiki, участники,
  подпаги и идентификаторы выделены по дисциплинам. Перенос проверен fixtures.
- TLine settings разделён на формы, таблицу, модели HTTP и hook загрузки;
  шесть поисковых экранов TBvolley используют одну конфигурируемую форму.
- `useGlobalSettings` и `services/globalSettings` объединяют повторявшийся доступ
  к настройкам и политику ошибок TableT/TBvolley.
- Комментарии объясняют этапы импорта, OCR, FIxt, KHL и TLine, порядок действий
  и инварианты данных. Нет механического «перевода» каждой строки кода.
- DB suites отделены от тестов без базы; общий gate доступен как `npm run check`.
- Один ESLint flat config; устаревший `.eslintrc.json` удалён, warnings запрещены.
- `.editorconfig` задаёт кодировку и отступы. Временные deployment-каталоги и
  вложенный клон исключены из инструментов анализа и Docker context.
- CI quality workflow запускается перед сборкой production image.
- Обновлены README корня, frontend/backend и архитектура; добавлены
  [путеводитель](CODE_GUIDE.md) и [инструкция проверок](TESTING.md).

## Закрытие оставшихся замечаний по повторному запросу

Все восемь групп конкретных замечаний первого прохода исправлены в локальном коде.
Дополнительно закрыты ошибки, обнаруженные при независимой проверке исправлений.

| Замечание | Исправление | Проверка |
|---|---|---|
| Публичная отправка с серверными credentials | Четыре эквивалентных send routes проверяют сессию и Origin до любых побочных действий; UI предлагает вход и один повтор | Auth API, `authenticatedRequest`, `admin-send-recovery` |
| DNS rebinding при отправке | Проверенный IP закреплён в соединении, Host/SNI и TLS сохранены; redirects запрещены | Реальные loopback HTTP/HTTPS/mTLS тесты |
| Фиктивная проверка proxy agent | Настоящий CONNECT/SOCKS transport; ограничения ответа и timeout до конца чтения | `proxyHealthProbe`, cron route tests |
| Неоднородные API guards и ошибки | DELETE/legacy mutations проверяют Origin, тела ограничены; ошибки API/import/AI/OCR/Prisma не раскрывают технические значения | API security/returned-error regressions |
| Process-local login limiter | Атомарный SQL upsert; лимит общий между процессами и рестартами, недоступная БД даёт 503 | PostgreSQL: 16 параллельных запросов через два клиента, ровно 8 разрешений |
| Plaintext admin password | Salted scrypt; CAS миграция legacy при успешном входе, включая env-login; env остаётся приоритетным | `adminCredentialStorage`, session security |
| Destructive force Liquipedia | Только сброс fetch cache; row lock охватывает проверку качества и публикацию матчей/участников; сохранены состав без расписания и приоритет главной страницы | `liquipediaSafeRefresh` на настоящей PostgreSQL |
| Крупные компоненты, normalizers, повторные формы и response any | Выделены контроллеры, модели и UI; доменные парсеры разнесены по этапам; HTTP-данные проверяются на границе | Parser fixtures, frontend unit и Playwright |
| Небезопасные deploy helpers | Offline default, ownership/port/image guards, immutable digest, backup, schema preflight и проверенный image rollback; `-Prune` запрещён | 6 PowerShell/validator tests и 11 Bash mock-сценариев |
| Дополнительные транзитивные уязвимости | Browserslist 4.28.9, xmldom 0.9.12, postcss-selector-parser 6.1.4; lock обновлён совместимо | `npm audit`: 0 уязвимостей после исправления |
| Несовпадение Origin в production NextURL | Восстановлен реальный валидированный Host без расширения доверия к proxy headers | Реальный браузерный вход, cookie и сессия после reload |
| Потеря данных формы TLine при ошибке | Редактор ждёт подтверждения сохранения, сохраняет черновик при refresh; неизвестное расписание нельзя перезаписать defaults | TLine settings recovery E2E |

Новая миграция `20260907190000_admin_login_rate_limit` создаёт таблицу и индекс;
она не меняет существующие таблицы или их данные. Перед будущей выкладкой её
нужно применить в подготовленное окружение. Deploy helper намеренно останавливается
при pending/failed migration: схема и её восстановление требуют отдельного окна.

## Границы и передача результата

- Сервер, production URL, live внешние парсеры, реальная Admin-отправка и нагрузка
  не проверялись. Docker daemon локально не был доступен; контейнерная сборка не
  заявляется проверенной. PostgreSQL-тесты выполнены через отдельный WSL cluster.
- На момент завершения локального аудита результат GitHub Actions ещё отсутствовал;
  публикация и проверки объединённой версии выполняются следующим этапом.
- История Git на секреты целиком не сканировалась; реальные `.env` и ключи не
  раскрывались. Проверены имена отслеживаемых секретоподобных файлов и политики ignore.
- `npm audit` выполнен для lockfile; после совместимых исправлений известных
  уязвимостей — 0. Это проверка advisory-базы npm, а не гарантия отсутствия
  неизвестных уязвимостей и не сканирование Docker base image.
- Полный accessibility-аудит, Firefox/WebKit и гарантии всех внешних парсеров
  остаются отдельными работами.
- Пользовательский diff безопасного логирования импорта команд сохранён.
  Исходные локальные `frontend/AGENTS.md` и `frontend/CLAUDE.md` не удалялись.
- На момент завершения локального аудита коммит, push и deploy не выполнялись.
  После выкладки auth v3 потребуется
  повторный вход; старые cookies намеренно становятся недействительными.

Для демонстрации: открыть README → архитектуру → путеводитель → транзакционный
import helper и соответствующий тест → этот отчёт с выполненными проверками.

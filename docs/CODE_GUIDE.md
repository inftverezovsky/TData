## Ручной импорт: от изображения до результата

```text
Принять текст или изображения
→ проверить формат, убрать дубликаты, применить лимит очереди
→ распознать данные через AI или OCR по правилам выбранного сценария
→ разобрать и нормализовать матчи
→ сопоставить участников со справочником Admin
→ дать оператору исправить неоднозначности и просмотреть результат
→ отправить выбранные готовые матчи по явному действию оператора
→ показать результат и сохранить нужное состояние интерфейса
```

В каталоге `components/manualImport/` основной workbench связывает этапы;
отдельные hooks управляют состоянием, распознаванием, очередью, сопоставлениями,
таблицей и отправкой. `api.ts` и `response.ts` отделяют HTTP и проверку ответа
от UI. Чистые модели и небольшие компоненты описывают отдельные шаги.
Это позволяет проверять вычисления без браузера, а сценарий — через Playwright.

На сервере [ocrPipeline.ts](../backend/src/manualImport/ocrPipeline.ts) управляет
обработкой изображения; [imageBatch.ts](../backend/src/manualImport/imageBatch.ts)
отвечает за уникальность и лимит. Эти ответственности не смешиваются.

## Импорт Liquipedia

```text
Проверить параметры обхода
→ получить основную страницу через API
→ найти и обработать подпаги ограниченными партиями
→ объединить и удалить дубликаты матчей
→ проверить полноту и качество новых данных
→ атомарно заменить матчи и участников либо сохранить предыдущий набор
→ вернуть успех, частичный результат или диагностируемую ошибку
```

[recursive.ts](../backend/src/sources/tdata/liquipedia/importer/recursive.ts)
содержит порядок шагов; отдельные `options.ts` и `persistence.ts` отвечают за
параметры и транзакцию. Некорректная concurrency не должна останавливать обход
навсегда; ошибка вставки не должна оставлять турнир без прежнего расписания.
`force` очищает только транспортный кэш. Сырые снимки, ручные привязки и прежние
данные остаются доступны при ошибке источника. Кандидаты участников также
публикуются только после общей проверки качества.

## TLine: фоновая проверка

[executor.ts](../backend/src/tline/application/executor.ts) связывает загрузку
источника, получение данных Admin, сопоставление и сравнение.
[jobs/repository.ts](../backend/src/tline/jobs/repository.ts) отвечает за
захват работы, срок владения job и восстановление после прерванного worker.

```text
Взять job с lease
→ проверить активность запуска
→ загрузить обе стороны сравнения
→ сохранить сравнения и состояние этапов
→ учесть отмену или ошибку
→ согласованно завершить job и run
```

Результат сравнения и ручное решение оператора имеют разные роли. Повторный
запуск не должен незаметно стирать ручные решения. Подробности: [TLINE.md](TLINE.md).

## КХЛ: доверие к ревизии

[repository.ts](../backend/src/results/khl/repository.ts) сохраняет исходный
снимок, нормализует данные и активирует только допустимую ревизию.
[delivery.ts](../backend/src/results/khl/delivery.ts) подготавливает результат
идемпотентно; staging не означает реальную сетевую отправку.

```text
Сохранить исходные факты
→ построить и проверить ревизию
→ подтвердить bindings
→ сформировать preview и hash
→ сравнить с предыдущей подготовкой
→ подготовить delivery только при выполнении всех условий
```

## Правило для комментариев

Хороший комментарий отвечает на один из вопросов: «какой здесь этап?»,
«почему порядок именно такой?», «что нельзя нарушить?» или «какой побочный
эффект выполняется?». Например: «Удаление и вставка выполняются в одной
транзакции, чтобы сбой вставки сохранил прежнее расписание».

Не нужно переводить каждую строку TypeScript на русский. `// Увеличить i`
не помогает читать алгоритм. Пояснения к простым типам и очевидным JSX-элементам
обычно избыточны. При изменении алгоритма обновляются и комментарий, и тест.

## Где искать новые границы ответственности

- `backend/src/normalizers/{dota2,counterstrike,leagueoflegends,valorant}/` —
  отдельно участники, HTML, wikitext, подпаги, идентификаторы и значения дат.
  Прежние `*Tournament.ts` остаются совместимыми точками входа.
- `frontend/src/components/tournament/teamMapping/` — таблица сопоставлений,
  клавиатурный выбор команды и контроллер сохранения.
- `frontend/src/components/tline/settings/` — отдельные формы, таблица маппинга,
  нормализация HTTP-ответов и hook состояния запросов.
- `frontend/src/components/tbvolley/TournamentSearchForm.tsx` — общая форма
  поиска; параметры и результаты каждого источника остаются в его адаптере.
- `backend/src/auth/credentials.ts`, `passwordHash.ts`, `loginRateLimit.ts` —
  приоритет runtime-пароля, scrypt и общий счётчик попыток входа в PostgreSQL.
- `backend/src/http/apiResponse.ts` — публичные ошибки и безопасная диагностика.
- `scripts/deploy/remote-redeploy.sh` — проверяемый порядок обновления и отката
  существующего проекта; PowerShell wrappers формируют план до `-Apply`.

Отправка во внешний Admin требует действующей сессии. Для ручного импорта и
турнирной панели 401 открывает форму входа и допускает один повтор того же
запроса после успешной авторизации. Другие ошибки не запускают скрытый повтор.

Форматирование выбранных файлов: `npm run format -- путь/к/файлу.tsx`.
Версия Prettier закреплена, параметры общие в `.prettierrc.json`; исходные
parser fixtures и исторические миграции исключены из автоматического форматирования.
[Установка и воспроизводимость Prettier](https://prettier.io/docs/install).
